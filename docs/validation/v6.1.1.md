# v6.1.1 手机音频兼容修复

## 问题与修复

用户提供的真机截图显示 `t.cancelAndHoldAtTime is not a function`。唯一调用位于 `GameAudio.duckMusic`：受伤、首领/符卡入场或危险预告时，背景音乐压低 4 dB，然后恢复。停火按钮本身不调用这个方法，无法仅凭截图判断当时是哪一个战斗事件触发。

[MDN 的 API 文档](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam/cancelAndHoldAtTime)标记该方法兼容性受限。之前的自动化和音频替身都提供该接口，未覆盖其缺失状态。

修复先检查方法是否存在。支持时继续使用原生 hold；不支持时，先读取当前增益、取消后续音量计划，再于当前音频时钟固定该增益。原有 30 ms 压低、250 ms 恢复不变，不修改操作、战斗数值、存档或素材。

## 验证

- 在修复前新增两项缺接口单测，均以相同 TypeError 失败，确认复现。
- 修复后音频、运行时战役、触控输入三文件共 **61 项通过**，其中音频 **17 项**；覆盖兼容分支、原生分支、连续危险提示、暂停清理与恢复。
- 旧版浏览器在移除 hold 接口后，触屏停火再受到真实敌人碰撞，生命降为 4，随即进入 error，错误与截图一致，见[复现记录](audio-compat-v6.1.1-before.json)。补丁版本相同路径继续运行，且实际调度音乐压低曲线；自动射击恢复、PALISADE 危险提示、暂停继续也通过。
- 类型、lint、五张原图以及已有素材哈希、生产构建检查通过。修复产物入口 `assets/index-2Wwam-9q.js`，SHA-256 `a863815ec2e65e41f9df111aebae20b98374f971162adab9ba9e6b3d107d14aa`。

完整移动浏览器套件 **25 项通过、3 项预期跳过、0 失败、0 flaky**，56.5 秒，见[逐项记录](audio-compat-v6.1.1-browser.json)。Windows Playwright WebKit 构建没有 AudioContext、webkitAudioContext 或 AudioParam，音频专项显式跳过；另两项仅限 Chromium CDP 的多指/滚动回归在 WebKit 跳过。该引擎其余移动流程继续检查静音回退，不能将其称为 Safari 真机音频验证。真机截图证明旧版实际故障；桌面注入缺失接口的复测仅验证此兼容路径，不代表已重测用户的同一台手机。
