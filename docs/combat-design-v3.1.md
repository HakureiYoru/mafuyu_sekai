# v3.1 战斗辨识与支援设计

本轮针对试玩反馈：敌弹与我方弹/经验混淆，地雷像道具，第 4–5 波火力吃紧，冲刺强化攻击缺少贯穿感。简洁主页维持现有布局。

## 调研依据与取舍

- 微软 [XAG 103](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/103) 建议用形状、文字等多种线索表达关键信息，颜色不能成为唯一依据。因此敌弹同时采用暖色、尖头和深色描边；地雷采用齿状实体与地面警戒圈；拾取物采用独立图标和浅色方形底座。近处道具才显示名称，避免整个战场堆满文字。
- Konami 对 [Gradius V 强化系统的介绍](https://www.konami.com/games/eu/es/topics/4694/) 提到通过拾取胶囊逐步取得更强武器和附加武器舱。这里借鉴“收集 → 支援火力成长”的结构；环绕自动瞄准、按波保证投放和受伤保留，是针对本项目试玩反馈作出的设计选择。
- [Kenney 在 OpenGameArt 发布的 Space Shooter Redux](https://opengameart.org/node/21238) 提供 CC0 素材。本轮仅引入少量子机与补给 PNG，其余缺少明确对应图形的道具采用本项目 SVG。具体来源、许可和哈希见 [素材说明](asset-sources-v3.1.md)。原五张 PNG 文件与路径保留。

不额外添加随机三选一、商店或长升级菜单。后两波的援助应当能按时到达，而不是要求已经吃力的玩家先达到更高等级。子机在本局受伤后保留，避免掉级进一步削弱全部支援。

## 首版实现参数

| 项目 | 行为 |
| --- | --- |
| 支援获取 | 第 2、3、4 波开始，在玩家附近投放一个可吸附的支援模块 |
| 子机上限 | 3 台，本局永久保留，继续无尽时保留；重新开始清空 |
| 支援火力 | 每台 0.6 秒一发，伤害 3，自动瞄准 560 单位内目标 |
| 资源 | 不耗玩家弹药、不加热；玩家停火或过热时继续掩护 |
| 活动范围 | 半径 92 的环绕队形，不增加玩家碰撞面积，不挡弹 |
| 超额模块 | 每份转为 30 XP；保留经验溢出与升级逻辑 |
| 冲刺强化 | 原 0.65 秒射击窗口内，下一枪变为瞬发光束 |
| 光束结算 | 长 2400、宽 88、伤害 40，沿走廊贯穿目标并清除敌弹，每目标每次仅结算一次 |
| 光束资源 | 消耗 1 弹药，该次发射不加热，过热期间也能释放；普通射击仍遵循热锁规则 |
| 光束显示 | 连续主束与短暂残光显示 0.32 秒；显示期间不重复扣血，低画质保留主束与危险提示 |

三台子机的理论总输出约 15 DPS。实际收益受射程、命中与目标分布影响；玩家仍需要主动射击、拾取和走位。光束提供可瞄准的局部解围机会，炸弹保留全场清敌弹的作用。

## 检查重点

固定步长下的子机射速与轨道一致性；自动火力不扣弹药/热量；掉级后保留、重开后清空；支援投放每波一次；光束几何与伤害一致、不会因残光重复命中；过热释放与弹量不足边界；道具与地雷在 720p 及低画质下仍能辨识。自动化只能验证机制和稳定性，最终强度仍依据下一轮实际试玩反馈调整。
