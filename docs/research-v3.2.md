# v3.2 敌人与 Boss：可读、可预判、可反击

研究日期：2026-09-11。代码基线：`9c3b577`。这是面向本项目的有限设计调研；下列时间、角度和组合上限是建议的首版试验值，不是来源游戏的参数，也不代表已经实施或完成平衡验收。

建议优先让攻击的预告成为可靠承诺，再增加敌人配合。玩家应能通过观察提前选择路线，并在成功躲避后获得输出机会。保留现有五类普通敌人即可完成首轮改进，无须增加复杂寻路、机器学习或新怪物数量。

## 当前问题的代码证据

基线 [config.ts](https://github.com/HakureiYoru/mafuyu_sekai/blob/9c3b5774d5024f01c5e11bc4fdf248857065bb02/src/game/config.ts) 的玩家速度为 300、半径为 18；Boss 激光预热 1.2 秒、最终锁向 0.4 秒、宽 96、持续 3.5 秒、角速度 0.55 rad/s。[simulation.ts](https://github.com/HakureiYoru/mafuyu_sekai/blob/9c3b5774d5024f01c5e11bc4fdf248857065bb02/src/game/simulation.ts) 的 `updateBoss()` 在预热剩余时间大于 0.4 秒时持续朝玩家瞄准，随后停止追踪；进入激光状态后又开始单向旋转。

因此，1.2 秒预热中的前 0.8 秒并不允许玩家把当前预告线当作最终攻击位置。最后 0.4 秒玩家最多正常移动 120 单位，而发射后攻击区域还会继续变化。对静止、无障碍的直线而言，侧移越过半宽与角色半径只需 66 单位，故不能单凭 0.4 秒断言攻击必然无法躲避；问题在于追瞄、旋转、距离以及其他攻击叠加后，提前走位的收益不清晰。

旋转光束在距离 `r` 处的切向速度约为 `r × 0.55`：距离 1000 时是 550 单位/秒，超过玩家 300。约在 545 单位之外，玩家便不能靠同方向沿圆周移动一直跑赢光束。这不等于所有位置都无解，但意味着设计不能把这种跑法当成通用解法，必须提前给出安全侧或完整扫过区域。

普通扫射怪当前每 10 tick 发一弹，方向每次跳转 1 rad（约 57.3°），没有独立预告/恢复状态。它有确定序列，但序列变化过大且不显示未来扇区。Boss 第三套攻击每 20 tick 重新读取玩家方向发三连弹，也没有整组攻击的固定朝向；因此玩家难以先规划一段安全路线。

## 首轮建议：把预告兑现为攻击

| 攻击 | 首版候选时序 | 承诺与反击规则 |
| --- | --- | --- |
| Boss 固定激光 | 搜索 0.35 秒 → 锁定 1.0 秒 → 发射 2.0 秒 → 恢复 1.0 秒 | 锁定同时保存原点、方向、宽度；发射期间不追瞄、不旋转。搜索线与已锁定走廊用形状和音效区分。 |
| 普通突进 | 搜索 0.2 秒 → 锁向预告 0.5 秒 → 有限直线突进 → 恢复 0.65 秒 | 保留少量提前量也只在锁定时采样；起冲后不得修正方向。显示实际冲刺线段，不能只有敌人发光。 |
| 普通狙击 | 搜索 0.25 秒 → 锁向 0.55 秒 → 单发 → 恢复 0.65 秒 | 预告结束后的玩家变向能确实骗过攻击。多个狙击手错开预告，不同时锁住玩家。 |
| 普通扫射 | 预告 0.8 秒 → 扫射 1.2 秒 → 恢复 1.0 秒 | 开始时确定整个约 80° 扇区、起点和左右方向；每 0.15 秒发一弹，在扇区内连续推进，不再每发跳 57°或追瞄。显示扇区边界和扫动箭头。 |

固定激光适合作为第一阶段的主要教学攻击。若第二阶段需要旋转激光，应把它作为有不同预告的新招：提前显示起止方向及完整扫过扇区，扫动方向在锁定时确定；攻击期间不得反向追玩家。先将扫过角限制在约 30°，再结合距离、墙边和其他危险验证可达的安全侧。仅调低角速度，或只画当前细线，都不足以证明公平。

恢复期不必让敌人完全失去碰撞或额外承伤；先用停止射击、显著减速和姿态变化制造稳定输出时间。所有攻击仍使用模拟时钟推进，暂停冻结，渲染只读取状态。

## 角色互补与组合约束

| 现有敌人 | 首要任务 | 首轮行为边界 |
| --- | --- | --- |
| basic | 从正面维持移动压力 | 部分个体缓慢选取玩家两侧位置，转向有速度上限；不全体精确预测玩家未来坐标。 |
| dasher | 惩罚停留，迫使横向换线 | 利用玩家最近约 0.2 秒的已发生移动决定初始方向；最终 0.5 秒只执行已承诺路线。 |
| sniper | 占据中远距离，要求一次明确侧移 | 保持距离和缓慢侧移；射前停稳，不能边高速后退边精确锁定。 |
| sprayer | 临时封住一个方向 | 封路区域可预先看见；不形成没有结束时间的全向连续扫射。 |
| minelayer | 使长期绕同一路线有代价 | 布雷前预告，地雷不会立即出现在玩家脚下；不能把当次 Boss 攻击唯一出口封死。 |

建议用轻量攻击调度器控制复杂度，首版不需要昂贵的全局路径规划：普通场景最多同时两次高威胁攻击处于锁定/攻击期；突进或狙击各占一个名额，扫射占两个。两个锁定时刻至少间隔 0.35 秒。获得名额之前可移动、找位置；获得后完整播放预告，不能等待完名额就立即出手。

Boss 激光独占高威胁名额，期间不开始新的狙击、扫射或布雷；已有危险需在进入预告前评估，不能只限制新生成实体。若预定出口被旧弹或地雷占据，延后激光或选择另一个候选方向。第一版组合池采用允许清单，例如“环弹 + 少量 basic”与“扫射恢复后接狙击”；不允许“激光 + 封出口地雷 + 两侧同时突进”。以上名额和间隔是本项目候选规则，来源并未提供这些固定数值。

## 弹幕缺口与 Boss 阶段

环弹不再仅依赖均匀分布自然留下的小缝。每组生成一个明确缺口：候选宽度 60°，0.9 秒前预告，中心取玩家当时方向附近的可达位置，锁定后同组各轮使用同一中心。需要改变缺口位置时，必须先结束该组，再对新位置重新预告。三连追瞄改为一组开始时锁向的短连射，组间才允许重新选角。

缺口不能只比较角度。对距离 `r`、玩家半径 18、弹半径 12、额外容错 16 的情形，两侧弹道间距至少应满足 `2 × r × sin(缺口角 / 2) ≥ 2 × (18 + 12 + 16)`。这个公式只是静态截面的最低检查；还须检查旧弹、移动敌人、墙体和到达该缺口的时间。不能把“某个时刻有空地”当成“玩家存在连续可行路线”。

Boss 可先试两个血量阶段（65% 以上 / 以下），生命值仍保持 1800 作为比较基线：第一阶段逐项展示固定激光、固定缺口环弹和锁向连射；第二阶段使用已经教过的攻击做受限组合，必要时引入有独立预告的短弧扫动。跨阶段在当前攻击及恢复结束后发生，并给 1.2 秒过渡；不得在玩家正按旧预告躲避时瞬间切换规则。避免连续重复同一种大招，恢复期不能被小怪瞬间填满。

先验证走位和输出机会，再调整血量与频率，使剧情全程继续面向 6–10 分钟、Boss 约 1–2 分钟的既定目标。更智能的敌人若只增加命中率而没有增加可理解的选择，不算完成这轮改进。

## 可实施的验收条件

- 对固定激光，锁定后让玩家左右反复变向，攻击原点和方向保持不变；预告区域与判定使用同一个几何描述。
- 冲刺在冷却、无炸弹、无无敌的条件下，分别从中距离、远距离、四个边缘和角落执行至少一条正常移动可躲避路线。测试明确记录预告出现、方向锁定、首次伤害的 tick。
- 扫射的第一发、最后一发与预告扇区一致；恢复期不发弹；同组环弹的缺口不会逐轮追着玩家移动。
- 组合测试包含旧弹未消散、地雷占位和小怪近身，确认调度不会安排互相封死出口的招式。用多个固定种子复现失败；路线采样仅是筛查工具，不能据此宣称所有随机局面都无解风险为零。
- 30/60/120/144 Hz 渲染下攻击选择、承诺时刻与判定一致；暂停、终局、重开清理攻击预约。低画质与减弱动态保留锁定状态、方向、边界和声音的主要提示。
- 真人首见试玩记录每次受伤原因是否能被说明，以及是否能指出下次可用的躲法。自动化无敌机器人用于稳定性，不用于证明这些攻击对普通玩家公平。
